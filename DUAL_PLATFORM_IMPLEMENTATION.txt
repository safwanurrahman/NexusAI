1. WAITER (main.py):
   ✓ Validates request via Pydantic
   ✓ Checks cache (now with platform in key)
   ✓ Dispatches task to Celery

   ✓ Returns combined results
   → Minimal enhancement (conditional logic)

4. SCOUTS (services/):
   ✓ linkedin_search.py (unchanged)
   + twitter_search.py (new, identical structure)
   → No breaking changes

5. TRANSLATOR (openai_ext.py):
   ✓ Summarizes articles
   → Unchanged

================================================================================
                         CACHING STRATEGY
================================================================================

NEW CACHE KEY FORMAT:
  {query}_{country}_{platform}

EXAMPLES:
  "python_us_linkedin"      → LinkedIn results only
  "python_us_twitter"       → Twitter results only
  "python_us_both"          → Both platforms combined

BENEFITS:
  ✓ Separate caching per platform
  ✓ Efficient: avoids re-searching one platform
  ✓ TTL: 3600 seconds (unchanged)
  ✓ In-memory dict (unchanged)
  ✓ No database migration needed

EXAMPLE:
  User searches "AI" (platform="both"):
    - Cache key: "ai_all_both"
    - If searched again: instant cache hit
    - If user searches "AI" with platform="linkedin":
      - Cache key: "ai_all_linkedin"
      - New search triggered (different key)

================================================================================
                         DATA FLOW DIAGRAM
================================================================================

FRONTEND:
  User Input → SearchBar (query + country, platform="both")
       ↓
  useArticleSearch.search(keyword, country)
       ↓
  POST /research {query, country, platform: "both"}
       ↓
BACKEND:
  main.py /research endpoint
    - Create cache_key: "{query}_{country}_{platform}"
    - Check cache (miss)
    - Dispatch: conduct_research_task.delay(query, country, platform)
       ↓
  worker.py conduct_research_task
    - If platform == "both":
      ├─ linkedin_results = search_linkedin(query, country)
      │  └─ Summarize each → ArticleSummary + platform="linkedin"
      └─ twitter_results = search_twitter(query, country)
         └─ Summarize each → ArticleSummary + platform="twitter"
    - Combine: all_articles = linkedin_results + twitter_results
    - Store in Redis
       ↓
  FRONTEND polls GET /results/{task_id}
       ↓
  Receive: [ArticleSummary, ...]
       ↓
  Map to Article[] with platform preserved
       ↓
FRONTEND DISPLAY:
  ArticleList separates by platform:
    - linkedInArticles = articles.filter(a => a.platform === "linkedin")
    - twitterArticles = articles.filter(a => a.platform === "twitter")
       ↓
  Two-Column Layout:
    Left Column: LinkedIn results with blue styling
    Right Column: Twitter results with sky blue styling
       ↓
  Each ArticleCard shows platform-specific styling + CTA button
