1. PROJECT OVERVIEW
================================================================================

PROJECT NAME: NexusAI - Intelligent LinkedIn Research Assistant

DESCRIPTION:
NexusAI is a full-stack research automation tool that extracts professional 
insights from LinkedIn. It processes user queries, searches LinkedIn content, 
and generates AI-powered 2-sentence summaries using OpenAI.

KEY FEATURES:
- Dual-Mode Deployment (Local development + Cloud production toggle)
- Asynchronous Background Processing (Celery + Redis with threading fallback)
- Intelligent Summarization (OpenAI GPT-4o-mini integration)
- Real-time Polling (Custom React hook for smooth UX)
- Country-based Filtering (Global or region-specific searches)
- Cache System (1-hour TTL for repeated queries)
- Task Management (Start, check status, and stop research tasks)

DEPLOYMENT TARGETS:
- Backend: Railway (API server)
- Frontend: Netlify (UI client)
- Local Development: Docker Compose

5. CORE FUNCTIONALITY & ARCHITECTURE
================================================================================

ARCHITECTURE PATTERN: "Waiter-Chef-Scout-Translator Model"

REQUEST FLOW (Happy Path):
1. Frontend User: Enters query + optional country, clicks "Search"
2. Waiter (FastAPI main.py):
   - Validates request via Pydantic schema
   - Checks in-memory cache (query_country key)
   - If cached: Returns immediately
   - If miss: Dispatches task to Celery + returns task_id
3. Conveyor (Redis):
   - Stores task metadata
   - Queues the job for workers
4. Chef (Celery worker in worker.py):
   - Receives task from queue
   - Calls Scout service (linkedin_search.py)
5. Scout (Serper API):
   - Searches LinkedIn with site:linkedin.com filter
   - Applies country filter (gl parameter) if specified
   - Returns 10 organic search results
6. Translator (OpenAI API):
   - For each result: Sends snippet to GPT-4o-mini
   - System prompt: "Summarize into 2 concise sentences"
   - Returns refined summary
7. Chef Assembly:
   - Builds ArticleSummary objects
   - Stores results in Redis via Celery backend
8. Waiter Polling:
   - Frontend polls GET /results/{task_id}
   - On completion: Caches result, returns success
9. Frontend Display:
   - Renders list of articles with title, author, link, summary

KEY ENDPOINTS:

POST /research
- Request: { query: string, country?: string }
- Response: { status: "processing"|"success"|"error", task_id?, data?, message? }
- Behavior: Checks cache, dispatches Celery task

GET /results/{task_id}
- Response: ResearchResponse with status update
- Behavior: Checks task state (pending/success/failure/revoked)

POST /research/stop/{task_id}
- Behavior: Revokes task with SIGKILL signal
- Cleanup: Removes metadata, clears cache if exists

GET /
- Health check endpoint

CACHING SYSTEM:
- TTL: 3600 seconds (1 hour)
- Key Format: "{query}_{country}" (both lowercased)
- Stored in: In-memory Python dict on API server
- Invalidation: On completion or expiration
- Benefit: Instant response for repeated searches

DATA MODELS (Pydantic):

ResearchRequest:
- query: str (required)
- country: str (optional, default="all")

ArticleSummary:
- title: str (default="Untitled Article")
- link: str (default="")
- author: str (default="Unknown")
- summary: str (required)

ResearchResponse:
- status: str ("processing"|"success"|"error"|"pending")
- data: List[ArticleSummary] (optional)
- task_id: str (optional)
- message: str (optional, for errors)

6. API INTEGRATIONS
================================================================================

SERPER API (LinkedIn Search):
- Endpoint: https://google.serper.dev/search
- Method: POST
- Auth: X-API-KEY header
- Query: site:linkedin.com {user_query}
- Params: num=10, gl={country_code} (optional)
- Returns: JSON with 'organic' array (title, link, snippet)

PROXYCURL API (LinkedIn Profile Data):
- Endpoint: https://nubela.co/proxycurl/api/v2/linkedin
- Method: GET
- Auth: Bearer token in Authorization header
- Params: url={linkedin_profile_url}
- Returns: Detailed profile data (name, experience, education, etc.)
- Note: Currently implemented but not actively used in search flow

OPENAI API (Summarization):
- Model: gpt-4o-mini
- Max Tokens: 150
- System Prompt: "Summarize LinkedIn content into 2 concise sentences"
- Input: Truncated snippet (max 800 chars to control costs)
- Output: 2-sentence summary
- Error Fallback: "Summary unavailable (Available in pro version)"

- Backend changes: Auto-reload via --reload flag
- Frontend changes: Vite hot module replacement
- Worker changes: Manual restart (docker-compose restart worker)
- Redis: Persists task queue

NPM SCRIPTS (Frontend):
- npm run dev: Start dev server
- npm run build: Production build
- npm run lint: ESLint check
- npm run test: Run tests
- npm run test:watch: Watch mode

TROUBLESHOOTING:
- Redis connection errors: Check REDIS_URL in config
- API key errors: Verify .env files
- CORS errors: Check BACKEND_CORS_ORIGINS in config
- Task failures: Check worker logs for stack traces
- Build issues: Clear node_modules and reinstall
